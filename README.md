# ASOFT Сервис

Внутренний веб-сервис сервисного центра: приём техники, этапы ремонта, задачи с уведомлениями, квитанции и акты в PDF, карточки клиентов. Один адаптивный сайт для телефона, планшета и компьютера.

Требования — в [`ТЗ-и-план.md`](ТЗ-и-план.md), решения по открытым вопросам — в [`ДОПУЩЕНИЯ.md`](ДОПУЩЕНИЯ.md).

## Что внутри

```
client/   React 18 + Vite + TypeScript, React Router, TanStack Query, React Hook Form + Zod, motion
server/   Node.js + Express + TypeScript, PostgreSQL (pg), сессии в httpOnly cookie, pdfmake
shared/   общие Zod-схемы, типы и матрица прав — одни и те же для клиента и сервера
e2e/      сценарии Playwright
scripts/  check-layout.mjs — обход экранов на всех ширинах и поиск горизонтального скролла
```

## Запуск с нуля

Нужны Node.js 20+ и PostgreSQL 14+.

1. Установить зависимости:

   ```bash
   npm install
   ```

2. Создать две базы — рабочую и для тестов:

   ```bash
   createdb servicedesk
   ```

   ```bash
   createdb servicedesk_test
   ```

3. Скопировать `.env.example` в `.env` и заполнить `DATABASE_URL`, `TEST_DATABASE_URL` и `SEED_PASSWORD` (пароль демо-сотрудников, от 8 символов).

4. Применить миграции и заполнить справочники и демо-данные:

   ```bash
   npm run db:seed
   ```

5. Запустить всё одной командой:

   ```bash
   npm run dev
   ```

   Откройте http://localhost:5179. API работает на порту `API_PORT` (по умолчанию 8431), Vite проксирует к нему `/api`.

### Демо-сотрудники

Пароль у всех — значение `SEED_PASSWORD` из вашего `.env`.

| Логин | Роль | Что может |
|---|---|---|
| `admin` | Руководитель системного администрирования | полный доступ: всё, включая справочники, сотрудников, реквизиты, импорт |
| `semen` | Директор | полный доступ, как у руководителя системного администрирования |
| `stas`, `olga` | Ведущий инженер | свои заявки и задачи, передача мастеру, акты |
| `lenya` | Инженер | свои заявки и задачи, акты |

Демо-данные: пять клиентов (одно юрлицо с чек-листом парка 60 ПК / 20 МФУ), семь заявок на разных этапах, просрочка, акт, цепочка передачи задачи.

## Команды

| Команда | Что делает |
|---|---|
| `npm run dev` | API и клиент с автоперезагрузкой |
| `npm run build` | сборка клиента в `client/dist` |
| `npm start` | API в продакшене; если есть `client/dist`, он же отдаёт сайт |
| `npm run db:migrate` | применить новые миграции из `server/src/db/migrations` |
| `npm run db:seed` | миграции + справочники; демо-данные — только в пустую базу |
| `npm run db:reset` | **удалить все данные** в базе из `DATABASE_URL` (в продакшене запрещено) |
| `npm test` | тесты API: этапы, права ролей, акты, задачи (база `TEST_DATABASE_URL`) |
| `npm run test:e2e` | Playwright: приём, ремонт до выдачи, юрлицо, массовое закрытие |
| `npm run typecheck` | проверка типов всех трёх пакетов |
| `node scripts/check-layout.mjs` | скриншоты экранов на 360–1440 px и поиск горизонтального скролла |

E2E и `check-layout` используют установленный Google Chrome (`PW_CHANNEL=msedge` — Edge). Скачивать браузеры Playwright не нужно.

## Уведомления в мессенджеры

Встроенные уведомления (всплывающие, колокольчик, лента) работают всегда, обновление идёт через SSE.

Внешние каналы подключаются токенами в `.env`. Без токена канал выключен, остальное работает.

- **Telegram:** создайте бота у @BotFather, токен — в `TELEGRAM_BOT_TOKEN`. Сотрудник пишет боту `/start`, узнаёт свой chat id (например, у @userinfobot) и вводит его в «Профиле». Кнопка «Проверить» шлёт тестовое сообщение.
- **Max:** токен бота платформы Max — в `MAX_BOT_TOKEN`, адрес API — в `MAX_API_URL`. Сотрудник пишет боту, бот отвечает его user id (сервер сам опрашивает Max, открытый адрес не нужен), сотрудник вводит id в «Профиле» и нажимает «Проверить».

Новый канал — это новая реализация интерфейса `NotificationChannel` в [`server/src/notify/channels.ts`](server/src/notify/channels.ts).

## Документы

PDF собирает сервер (pdfmake, шрифт Roboto с кириллицей из самого пакета). Вёрстка квитанции и акта лежит отдельно от кода маршрутов: [`server/src/documents/templates`](server/src/documents/templates). Реквизиты, условия и текст о скидке правятся в «Настройках → Реквизиты и документы».

## Безопасность

- Пароли — bcrypt. Сессия — случайный токен в httpOnly cookie, в базе хранится только его SHA-256.
- CSRF: токен сессии в заголовке `X-CSRF-Token` на всех изменяющих запросах + проверка `Origin`.
- Вход: не больше 5 неудачных попыток на пару «IP + логин» за 15 минут.
- Права проверяются на каждом маршруте API (`shared/src/roles.ts`), кнопки в интерфейсе только дублируют их.
- SQL — только параметризованные запросы.
- Вложения: белый список расширений и MIME, проверка сигнатуры файла, лимит размера, случайные имена в `uploads/` (папка вне git).
- Секреты — только в `.env`, который не попадает в git.

## Продакшен

1. `npm run build`.
2. В `.env`: `NODE_ENV=production`, `COOKIE_SECURE=true` (сайт по HTTPS), `PUBLIC_URL` и `ALLOWED_ORIGINS` с реальным адресом.
3. `npm start` за обратным прокси (nginx, Caddy). Для SSE отключите буферизацию ответа на `/api/events`.
4. Бэкап: база PostgreSQL и папка `uploads/`.
