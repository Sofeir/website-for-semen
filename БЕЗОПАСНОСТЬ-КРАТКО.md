# Безопасность сервиса: коротко и простым языком

Подробная версия лежит рядом: `БЕЗОПАСНОСТЬ.md`.

## Что сделано

- **Пароли.** Хранятся в зашифрованном виде, подобрать их по украденной базе очень долго. Простые пароли (12345678, qwerty123, пароль с логином) не принимаются.
- **Защита входа.** Подбор пароля останавливается: после нескольких неудач вход временно закрывается или идёт по очереди. Директора с верным паролем это не запирает.
- **Ограничения на запросы.** Нельзя завалить сайт тысячами запросов, нельзя массово регистрировать фальшивых заказчиков.
- **Права.** Каждый видит только своё: мастер не видит чужие заявки, заказчик только свой кабинет, помощник только задачи. Проверяется на сервере, а не на экране.
- **Файлы.** Принимаются только фото, видео, PDF, Word, Excel и текст, содержимое проверяется. В чужую заявку файл прикрепить нельзя.
- **Вход под защитой https.** Когда включён домен, всё общение идёт в зашифрованном виде, а вход нельзя подделать с соседних сайтов.
- **Выгрузки Excel и CSV** не выполняют вредные формулы.
- **Уведомления на телефон и компьютер** приходят только от настоящих служб браузеров.
- **Зависимости** обновлены там, где были известные уязвимости.

## Что осталось (не страшно, но стоит сделать)

- Двухфакторный вход для директора и администратора (код из приложения).
- Подтверждение телефона по СМС при регистрации заказчика (платный сервис).
- Обновить библиотеку проверки данных (zod): это отдельная большая задача.

## Что должен сделать Ваня на сервере

1. Закрыть лишние порты: оставить 80, 443 и SSH. После запуска домена закрыть порт 50080.
2. Вход на сервер по SSH только по ключу, поставить `fail2ban`.
3. Включить автоматические обновления системы.
4. `chmod 600 .env`: файл с паролями доступен только владельцу.
5. Хранить копии базы ещё и в другом месте, не только на этом сервере.
6. Раз в месяц обновлять образы: `docker compose pull && docker compose up -d --build`.
