# Как перевести сервис на домен crm.adminstart.ru

Файл для того, кто настраивает: сейчас сервис открывается по адресу http://37.79.202.96:50080, после настройки он будет открываться по https://crm.adminstart.ru. Сам сайт на adminstart.ru не меняется: сервис живёт на отдельном поддомене `crm`, чтобы рекламный трафик не попадал в рабочий сервис.

## Что нужно заранее

1. **Доступ к управлению доменом.** Это личный кабинет того, у кого куплен adminstart.ru (регистратор или хостинг), раздел «DNS» или «Управление записями».
2. **Вход на сервер.** Нужен логин с правом `sudo` и возможность подключиться по SSH к серверу 37.79.202.96. Папка проекта на сервере: `/opt/servicedesk`.
3. **Открытые порты 80 и 443.** Сейчас снаружи открыт только 50080. На роутере или в панели хостера нужно пробросить на сервер порты 80 и 443. Порт 80 нужен даже для https: через него Let's Encrypt проверяет, что домен принадлежит вам.
4. **Выложенная версия сервиса.** Скрипт установки появился в последних правках. Пока вы не скажете «выложи», на сервере его нет.

Если своего сертификата на домен нет или он не нужен, ничего покупать не надо: скрипт сам выпустит бесплатный сертификат Let's Encrypt и сам будет его продлевать. Если у вас уже есть купленный сертификат, который нужно использовать именно его, скажите об этом заранее: настройка будет немного другой.

## Шаги

**Шаг 1. Запись в DNS.** В кабинете домена добавьте запись:

| Тип | Имя | Значение |
| --- | --- | --- |
| A | crm | 37.79.202.96 |

Запись для самого adminstart.ru не меняйте. Обновление занимает от нескольких минут до пары часов. Проверка с любого компьютера:

```bash
nslookup crm.adminstart.ru
```

В ответе должен быть адрес 37.79.202.96.

**Шаг 2. Порты.** Пробросьте на сервер порты 80 и 443. Если на сервере включён фильтр `ufw`, откройте их там тоже:

```bash
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
```

**Шаг 3. Резервная копия.** На случай, если что-то пойдёт не так:

```bash
cd /opt/servicedesk
bash deploy/backup.sh
```

**Шаг 4. Установка домена.** На сервере, в папке проекта:

```bash
cd /opt/servicedesk
git pull
sudo bash deploy/enable-domain.sh crm.adminstart.ru ПОЧТА
```

Вместо `ПОЧТА` впишите рабочий адрес электронной почты: на него Let's Encrypt шлёт предупреждения, если сертификат перестанет продлеваться. Скрипт сам:
- проверит, что домен указывает на этот сервер;
- выпустит бесплатный сертификат;
- включит https и перенаправление с http на https;
- пропишет новые адреса в настройках (`.env`; прежний файл сохранится как `.env.before-domain`);
- перезапустит приложение и поставит автоматическое продление сертификата.

Скрипт можно запускать повторно. Если запись DNS ещё не обновилась, он так и скажет: подождите и запустите снова.

**Шаг 5. Проверка.** Откройте https://crm.adminstart.ru. Должен открыться вход в сервис, в адресной строке замок. Войдите своим логином.

**Шаг 6. Закройте старый адрес.** Когда убедились, что новый адрес работает, закройте на роутере внешний порт 50080. Старая ссылка с `:50080` после этого не нужна.

## Что изменится для сотрудников

- Вход теперь только по адресу https://crm.adminstart.ru. Старую закладку с IP нужно заменить.
- Заново входить придётся один раз: сессия привязана к адресу.
- Браузер сможет показывать всплывающие уведомления сайта, а телефон и Chrome предложат установить сервис как приложение. По http и по адресу без домена это не работало.
- Ссылка «Открыть в сервисе» в сообщениях Max будет вести на новый адрес.

## Если что-то не получилось

- **Скрипт пишет, что домен указывает не на этот сервер.** DNS ещё не обновился, либо в записи A указан другой адрес. Подождите и запустите снова.
- **Сертификат не выпустился.** Порт 80 снаружи не доходит до сервера. Проверьте проброс на роутере и `sudo ufw status`.
- **Сайт не открылся после установки.** Посмотрите журнал: `sudo docker compose logs --tail 30 app angie`.
- **Нужно вернуть как было.** Верните прежний файл настроек и перезапустите приложение:

```bash
cd /opt/servicedesk
cp .env.before-domain .env
sudo rm /etc/servicedesk-https/crm.adminstart.ru.conf
sudo docker compose up -d --force-recreate app angie
```

Сервис снова откроется по старому адресу.
