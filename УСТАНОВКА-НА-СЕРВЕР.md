# Установка на сервер (Ubuntu + PostgreSQL)

Сервис работает без Docker: Node.js запускает сервер, PostgreSQL уже стоит на машине. Сервер сам отдаёт сайт, nginx для работы в локальной сети не нужен.

Адрес сайта после установки: `http://АДРЕС_СЕРВЕРА:8431`.

## Что подготовить заранее (на компьютере, где сейчас лежат данные)

1. Открыть сайт в том браузере, где вносили данные. Данные хранятся в браузере и не видны с других компьютеров и из других браузеров.
2. На экране входа нажать **«Скачать все данные для переноса на сервер»**. Скачается файл `asoft-servicedesk-ГГГГ-ММ-ДД.sql`.
3. Положить файл в надёжное место. Это полная копия: схема и все данные. Копию можно скачивать сколько угодно раз. Перед боевым переносом скачайте её заново, чтобы не потерять свежие записи.

## Установка

Все команды на сервере. `ПАРОЛЬ` и `АДРЕС_СЕРВЕРА` замените своими.

### 1. База данных

Отдельная база и отдельный пользователь, не связанные с другими программами:

```bash
sudo -u postgres psql -c "CREATE USER servicedesk WITH PASSWORD 'ПАРОЛЬ';"
sudo -u postgres psql -c "CREATE DATABASE servicedesk OWNER servicedesk;"
```

### 2. Загрузка данных одной командой

```bash
PGPASSWORD='ПАРОЛЬ' psql -h localhost -U servicedesk -d servicedesk -v ON_ERROR_STOP=1 -f asoft-servicedesk-ГГГГ-ММ-ДД.sql
```

Файл создаёт все таблицы и загружает все записи в одной транзакции. Если что-то пойдёт не так, откатится всё и база останется пустой. Тогда можно исправить причину и запустить ту же команду снова. Если база уже заполнена, удалите её и создайте заново.

То же самое можно сделать в pgAdmin: Query Tool → открыть файл → выполнить. Через `psql` надёжнее для большого файла.

### 3. Программа

```bash
sudo apt install -y git
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
sudo apt install -y nodejs
sudo git clone https://github.com/Sofeir/website-for-semen.git /opt/servicedesk
cd /opt/servicedesk
sudo npm ci
sudo npm run build
```

Файл `/opt/servicedesk/.env`:

```
NODE_ENV=production
DATABASE_URL=postgres://servicedesk:ПАРОЛЬ@localhost:5432/servicedesk
API_PORT=8431
PUBLIC_URL=http://АДРЕС_СЕРВЕРА:8431
ALLOWED_ORIGINS=http://АДРЕС_СЕРВЕРА:8431
COOKIE_SECURE=false
APP_NAME="ASOFT Сервис"
APP_TIMEZONE=Asia/Yekaterinburg
UPLOAD_DIR=/var/lib/servicedesk/uploads
```

`COOKIE_SECURE=true` ставить только когда сайт откроется по https.

```bash
sudo mkdir -p /var/lib/servicedesk/uploads
```

### 4. Автозапуск

Файл `/etc/systemd/system/servicedesk.service`:

```
[Unit]
Description=ASOFT Сервис
After=network.target postgresql.service

[Service]
WorkingDirectory=/opt/servicedesk
ExecStart=/usr/bin/npm start
Restart=always
User=root

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now servicedesk
sudo systemctl status servicedesk
```

Логи: `journalctl -u servicedesk -f`. Если порт закрыт файрволом: `sudo ufw allow 8431/tcp`.

### 5. Проверка

Открыть `http://АДРЕС_СЕРВЕРА:8431` с другого компьютера в сети (или через VPN). Войти.

**Пароль после переноса.** Все сотрудники из демо-базы имеют пароль `demo`. Сразу после переноса:
- зайти директором и сменить пароли в разделе сотрудников;
- реальных сотрудников завести из файла: `staff.local.json` положить в `/opt/servicedesk` и выполнить `sudo npm run staff:import --workspace server`. Файл с настоящими телефонами в GitHub не хранится, его переносят вручную.

## Обновление программы

Вручную:

```bash
cd /opt/servicedesk
sudo git pull
sudo npm ci
sudo npm run build
sudo systemctl restart servicedesk
```

Миграции базы применяются сами при старте.

## Автоматическое обновление из GitHub (когда всё будет работать)

Цепочка: изменения попадают в ветку на GitHub, автослияние переносит их в `main`, сервер раз в минуту проверяет `main` и обновляется. Репозиторий публичный, ключи и токены не нужны. Сервер сам ходит на GitHub, поэтому закрытая сеть не мешает. Нужен только выход сервера в интернет.

Файл `/opt/servicedesk/deploy-update.sh`:

```bash
#!/bin/bash
set -e
cd /opt/servicedesk
git fetch -q origin main
if [ "$(git rev-parse HEAD)" != "$(git rev-parse origin/main)" ]; then
  git merge -q --ff-only origin/main
  npm ci --silent
  npm run build --silent
  systemctl restart servicedesk
  echo "$(date) обновлено до $(git rev-parse --short HEAD)" >> /var/log/servicedesk-update.log
fi
```

```bash
sudo chmod +x /opt/servicedesk/deploy-update.sh
echo '* * * * * root /opt/servicedesk/deploy-update.sh' | sudo tee /etc/cron.d/servicedesk-update
```

Данные при обновлении не затрагиваются: база живёт в PostgreSQL, вложения в `/var/lib/servicedesk/uploads`.

## Резервные копии

Раз в сутки копия базы, хранится 14 дней. Файл `/etc/cron.d/servicedesk-backup`:

```
0 3 * * * postgres mkdir -p /var/backups/servicedesk && pg_dump servicedesk | gzip > /var/backups/servicedesk/servicedesk-$(date +\%F).sql.gz && find /var/backups/servicedesk -mtime +14 -delete
```

Восстановление: пустая база, затем `gunzip -c файл.sql.gz | psql -d servicedesk`. Папку `/var/lib/servicedesk/uploads` копируют вместе с базой.
