# Установка на сервер (Ubuntu + PostgreSQL + Docker + Nginx)

Схема:

```
сотрудники → Nginx (порт 80/443) → приложение (порт 8431, Docker) → PostgreSQL (на самом сервере)
```

- **PostgreSQL** уже стоит на сервере. В Docker его не кладём: данные остаются в обычной базе, с ней работает pgAdmin.
- **Приложение** (сайт и сервер) и **Nginx** работают в двух контейнерах Docker. Описаны в `docker-compose.yml`, `Dockerfile` и `deploy/nginx.conf`.
- Контейнеры работают в сети самого сервера (`network_mode: host`). Поэтому в `.env` база указывается как `localhost`, и в PostgreSQL ничего открывать не нужно.

Адрес сайта после установки: `http://АДРЕС_СЕРВЕРА` (без номера порта).

## Что подготовить заранее (на компьютере, где сейчас лежат данные)

1. Открыть сайт в том браузере, где вносили данные. Данные хранятся в браузере и не видны с других компьютеров и из других браузеров.
2. На экране входа нажать **«Скачать все данные для переноса на сервер»**. Скачается файл `asoft-servicedesk-ГГГГ-ММ-ДД.sql`.
3. Положить файл в надёжное место и скопировать на сервер. Это полная копия: схема и все данные. Скачивать её можно сколько угодно раз. Перед боевым переносом скачайте заново, чтобы не потерять свежие записи.

## Установка

Все команды на сервере. `ПАРОЛЬ` и `АДРЕС_СЕРВЕРА` замените своими. Пароль базы придумайте сами и запишите.

### 1. База данных

Отдельная база и отдельный пользователь, не связанные с другими программами:

```bash
sudo -u postgres psql -c "CREATE USER servicedesk WITH PASSWORD 'ПАРОЛЬ';"
sudo -u postgres psql -c "CREATE DATABASE servicedesk OWNER servicedesk;"
```

### 2. Загрузка данных одной командой

```bash
PGPASSWORD='ПАРОЛЬ' psql -h localhost -U servicedesk -d servicedesk -v ON_ERROR_STOP=1 -f asoft-servicedesk-ГГГГ-ММ-ДД.sql
```

Файл создаёт все таблицы и загружает все записи в одной транзакции. Если что-то пойдёт не так, откатится всё и база останется пустой. Тогда исправьте причину и запустите ту же команду снова. Если база уже заполнена, удалите её (`DROP DATABASE servicedesk;`) и создайте заново.

То же самое можно сделать в pgAdmin: Query Tool → открыть файл → выполнить. Через `psql` надёжнее для большого файла.

### 3. Docker и программа

```bash
sudo apt update
sudo apt install -y git
curl -fsSL https://get.docker.com | sudo sh
sudo git clone https://github.com/Sofeir/website-for-semen.git /opt/servicedesk
cd /opt/servicedesk
sudo mkdir -p /var/lib/servicedesk/uploads
```

Файл `/opt/servicedesk/.env` (значения без кавычек):

```
DATABASE_URL=postgres://servicedesk:ПАРОЛЬ@localhost:5432/servicedesk
API_PORT=8431
PUBLIC_URL=http://АДРЕС_СЕРВЕРА
ALLOWED_ORIGINS=http://АДРЕС_СЕРВЕРА
COOKIE_SECURE=false
APP_NAME=ASOFT Сервис
APP_TIMEZONE=Asia/Yekaterinburg
```

Если сотрудники будут открывать сайт и по IP, и по имени компьютера, перечислите оба адреса через запятую в `ALLOWED_ORIGINS`.

`NODE_ENV` и папку вложений задаёт `docker-compose.yml`, в `.env` их писать не нужно. Вложения лежат на сервере в `/var/lib/servicedesk/uploads` и при обновлении не теряются.

### 4. Запуск

```bash
cd /opt/servicedesk
sudo docker compose up -d --build
```

Первая сборка занимает несколько минут. После неё оба контейнера стартуют сами и поднимаются заново после перезагрузки сервера.

Файрвол, если включён:

```bash
sudo ufw allow 80/tcp
```

Порт 8431 наружу открывать не нужно: к приложению ходит только Nginx.

### 5. Проверка

```bash
sudo docker compose ps
sudo docker compose logs --tail 30 app
curl -I http://localhost
```

В логах приложения должна быть строка `API: http://localhost:8431`. Затем откройте `http://АДРЕС_СЕРВЕРА` с другого компьютера в сети (или через VPN) и войдите.

**Пароль после переноса.** Все сотрудники из демо-базы имеют пароль `demo`. Сразу после переноса:
- зайти директором и сменить пароли в разделе сотрудников;
- реальных сотрудников завести из файла: положить `staff.local.json` в `/opt/servicedesk` и выполнить `sudo docker compose exec app npm run staff:import --workspace server`. Файл с настоящими телефонами в GitHub не хранится, его переносят вручную. Он находится вне образа, поэтому перед командой скопируйте его в контейнер: `sudo docker compose cp staff.local.json app:/app/staff.local.json`.

## Полезные команды

Все выполняются в `/opt/servicedesk`.

| Что нужно | Команда |
|---|---|
| Состояние контейнеров | `sudo docker compose ps` |
| Логи приложения (live) | `sudo docker compose logs -f app` |
| Логи Nginx | `sudo docker compose logs -f nginx` |
| Перезапустить всё | `sudo docker compose restart` |
| Остановить | `sudo docker compose down` |
| Запустить | `sudo docker compose up -d` |

Данные при `down` не пропадают: они в PostgreSQL и в `/var/lib/servicedesk/uploads`.

## Обновление программы

Вручную:

```bash
cd /opt/servicedesk
sudo git pull
sudo docker compose up -d --build
```

Миграции базы применяются сами при старте приложения.

## Автоматическое обновление из GitHub (когда всё будет работать)

Цепочка: изменения попадают в ветку на GitHub, автослияние переносит их в `main`, сервер раз в минуту проверяет `main` и обновляется. Репозиторий публичный, ключи и токены не нужны. Сервер сам ходит на GitHub, поэтому закрытая сеть не мешает. Нужен только выход сервера в интернет.

Скрипт уже лежит в репозитории: `deploy/update.sh`. Подключить:

```bash
sudo chmod +x /opt/servicedesk/deploy/update.sh
echo '* * * * * root /opt/servicedesk/deploy/update.sh' | sudo tee /etc/cron.d/servicedesk-update
```

Журнал обновлений: `/var/log/servicedesk-update.log`. Если нужно остановить автообновление: `sudo rm /etc/cron.d/servicedesk-update`.

## HTTPS (когда понадобится)

Домен для https не нужен: сойдёт собственный сертификат. Браузер при первом открытии покажет предупреждение, его подтверждают один раз.

1. Создать сертификат на 10 лет:

```bash
sudo mkdir -p /etc/servicedesk-ssl
sudo openssl req -x509 -nodes -days 3650 -newkey rsa:2048 \
  -keyout /etc/servicedesk-ssl/servicedesk.key -out /etc/servicedesk-ssl/servicedesk.crt \
  -subj "/CN=АДРЕС_СЕРВЕРА" -addext "subjectAltName=IP:АДРЕС_СЕРВЕРА"
```

2. В `deploy/nginx.conf` раскомментировать блок `server { listen 443 ssl ... }` в конце файла.
3. В `.env` заменить адреса на `https://АДРЕС_СЕРВЕРА` (`PUBLIC_URL`, `ALLOWED_ORIGINS`) и поставить `COOKIE_SECURE=true`.
4. Открыть порт и перезапустить:

```bash
sudo ufw allow 443/tcp
cd /opt/servicedesk && sudo docker compose up -d --force-recreate
```

После покупки домена вместо собственного сертификата ставится бесплатный от Let's Encrypt (certbot). Это отдельный небольшой шаг.

## Резервные копии

Раз в сутки копия базы, хранится 14 дней. Файл `/etc/cron.d/servicedesk-backup`:

```
0 3 * * * postgres mkdir -p /var/backups/servicedesk && pg_dump servicedesk | gzip > /var/backups/servicedesk/servicedesk-$(date +\%F).sql.gz && find /var/backups/servicedesk -mtime +14 -delete
```

Восстановление: пустая база, затем `gunzip -c файл.sql.gz | psql -d servicedesk`. Папку `/var/lib/servicedesk/uploads` копируют вместе с базой.

## Если что-то не работает

- **Сайт не открывается.** `sudo docker compose ps`: оба контейнера должны быть `running`. Затем `sudo ufw status`: порт 80 открыт.
- **Приложение не стартует, в логах про базу.** Проверьте `DATABASE_URL` в `.env` и что PostgreSQL запущен: `sudo systemctl status postgresql`. После правки `.env`: `sudo docker compose up -d --force-recreate`.
- **Вход не проходит или «Запрещено».** Адрес в браузере должен совпадать с одним из адресов в `ALLOWED_ORIGINS`, включая `http` или `https`.
- **Уведомления приходят с задержкой.** Проверьте, что в `deploy/nginx.conf` для `/api/events` стоит `proxy_buffering off`.
