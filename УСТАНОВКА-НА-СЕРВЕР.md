# Установка на сервер (Ubuntu + Docker)

Всё работает в Docker, три контейнера:

```
сотрудники → Angie (порт 80/443) → приложение (сайт и сервер, порт 8431) → PostgreSQL
```

- **db**: PostgreSQL 16. Данные лежат в томе Docker `pgdata`.
- **app**: сайт и сервер. Вложения лежат в томе `uploads`.
- **angie**: прокси-сервер (российская замена nginx, настройки совместимы). Единственный, кто открыт наружу.

Описание лежит в `docker-compose.yml` (три контейнера), `Dockerfile` (сборка приложения) и `deploy/angie.conf` (прокси). Ставить на сервере нужны только Docker и git: ни Node.js, ни PostgreSQL отдельно не нужны.

Адрес сайта после установки: `http://АДРЕС_СЕРВЕРА` (без номера порта).

## Что подготовить заранее (на компьютере, где сейчас лежат данные)

1. Открыть сайт в том браузере, где вносили данные. Данные хранятся в браузере и не видны с других компьютеров и из других браузеров.
2. На экране входа нажать **«Скачать все данные для переноса на сервер»**. Скачается файл `asoft-servicedesk-ГГГГ-ММ-ДД.sql`.
3. Положить файл в надёжное место и скопировать на сервер. Это полная копия: схема и все данные. Скачивать её можно сколько угодно раз. Перед боевым переносом скачайте заново, чтобы не потерять свежие записи.

## Установка

Все команды на сервере. `ПАРОЛЬ` и `АДРЕС_СЕРВЕРА` замените своими.

### 1. Docker и программа

```bash
sudo apt update
sudo apt install -y git
curl -fsSL https://get.docker.com | sudo sh
sudo git clone https://github.com/Sofeir/website-for-semen.git /opt/servicedesk
cd /opt/servicedesk
```

### 2. Настройки

Файл `/opt/servicedesk/.env` (значения без кавычек):

```
DB_PASSWORD=ПАРОЛЬ
PUBLIC_URL=http://АДРЕС_СЕРВЕРА
ALLOWED_ORIGINS=http://АДРЕС_СЕРВЕРА
COOKIE_SECURE=false
APP_NAME=ASOFT Сервис
APP_TIMEZONE=Asia/Yekaterinburg
```

- `DB_PASSWORD`: придумайте пароль базы из латинских букв и цифр (без `@`, `#`, `/`, `$`), запишите его. Этим паролем защищена база; наружу она не открыта.
- Если сотрудники будут открывать сайт и по IP, и по имени компьютера, перечислите оба адреса через запятую в `ALLOWED_ORIGINS`.
- Адрес базы и папку вложений задаёт `docker-compose.yml`, в `.env` их писать не нужно.

### 3. База и загрузка данных

Сначала запускаем только базу и загружаем в неё данные. Приложение пока не запускаем: при первом старте оно само создаёт пустые таблицы, а файл данных создаёт их сам.

```bash
cd /opt/servicedesk
sudo docker compose up -d db
sudo docker compose ps
```

Подождать, пока у `db` в таблице появится `healthy` (обычно до минуты). Затем загрузить файл одной командой:

```bash
sudo docker compose exec -T db psql -U servicedesk -d servicedesk -v ON_ERROR_STOP=1 < asoft-servicedesk-ГГГГ-ММ-ДД.sql
```

Файл создаёт все таблицы и загружает все записи в одной транзакции. Если что-то пойдёт не так, откатится всё и база останется пустой. Тогда исправьте причину и запустите ту же команду снова.

Если в базе уже есть таблицы (например, после неудачного запуска приложения), очистите её и повторите:

```bash
sudo docker compose exec -T db psql -U servicedesk -d postgres -c "DROP DATABASE servicedesk;" -c "CREATE DATABASE servicedesk OWNER servicedesk;"
```

### 4. Запуск

```bash
cd /opt/servicedesk
sudo docker compose up -d --build
```

Первая сборка занимает несколько минут. После неё все три контейнера стартуют сами и поднимаются заново после перезагрузки сервера. Миграции базы приложение применяет само.

Файрвол, если включён:

```bash
sudo ufw allow 80/tcp
```

Порты базы и приложения наружу открывать не нужно.

### 5. Проверка

```bash
sudo docker compose ps
sudo docker compose logs --tail 30 app
curl -I http://localhost
```

В логах приложения должна быть строка `API: http://localhost:8431`. Затем откройте `http://АДРЕС_СЕРВЕРА` с другого компьютера в сети (или через VPN) и войдите.

**Пароль после переноса.** Все сотрудники из демо-базы имеют пароль `demo`. Сразу после переноса:
- зайти директором и сменить пароли в разделе сотрудников;
- реальных сотрудников завести из файла: положить `staff.local.json` в `/opt/servicedesk`, затем:

```bash
sudo docker compose cp staff.local.json app:/app/staff.local.json
sudo docker compose exec app npm run staff:import --workspace server
```

Файл с настоящими телефонами в GitHub не хранится, его переносят вручную.

## Подключение pgAdmin к базе

База открыта только на самом сервере, порт 5433 (чтобы не мешать другим базам на сервере). С другого компьютера подключаются через SSH-туннель: в pgAdmin на вкладке SSH Tunnel указать сервер, а в параметрах подключения хост `localhost`, порт `5433`, база `servicedesk`, пользователь `servicedesk`, пароль из `.env`.

Быстро посмотреть базу без pgAdmin: `sudo docker compose exec db psql -U servicedesk -d servicedesk`.

## Полезные команды

Все выполняются в `/opt/servicedesk`.

| Что нужно | Команда |
|---|---|
| Состояние контейнеров | `sudo docker compose ps` |
| Логи приложения (live) | `sudo docker compose logs -f app` |
| Логи Angie | `sudo docker compose logs -f angie` |
| Логи базы | `sudo docker compose logs -f db` |
| Перезапустить всё | `sudo docker compose restart` |
| Остановить | `sudo docker compose down` |
| Запустить | `sudo docker compose up -d` |

**Не используйте `docker compose down -v`**: ключ `-v` удаляет тома, то есть всю базу и вложения. Обычный `down` данные не трогает.

## Обновление программы

Вручную (берёт ту версию, которую владелец выложил на сервер, см. ниже):

```bash
sudo /opt/servicedesk/deploy/update.sh
```

Миграции базы применяются сами при старте приложения. Пересобирается только приложение, база и данные не затрагиваются.

## Автоматическое обновление из GitHub

Что попадёт на сервер, решает владелец. Изменения в `main` на сервер сами не идут. Сервер раз в минуту смотрит ветку `release` и обновляется, только когда она сдвинулась. Её сдвигает кнопка на GitHub: **Actions → «Выложить на сервер» → Run workflow**. По умолчанию выкладывается текущий `main`. В поле можно указать другой коммит или ветку: так делается откат на прежнюю версию. Через минуту-две сервер пересоберётся (журнал: `/var/log/servicedesk-update.log`).

Репозиторий публичный, ключи и токены не нужны. Сервер сам ходит на GitHub, поэтому закрытая сеть не мешает. Нужен только выход сервера в интернет.

Если на сервере вручную правили файлы программы (например, включили https в `deploy/angie.conf`), скрипт обновление пропускает и пишет об этом в журнал: иначе он затёр бы правки.

Скрипт уже лежит в репозитории: `deploy/update.sh`. Подключить:

```bash
sudo chmod +x /opt/servicedesk/deploy/update.sh
echo '* * * * * root /opt/servicedesk/deploy/update.sh' | sudo tee /etc/cron.d/servicedesk-update
```

Журнал обновлений: `/var/log/servicedesk-update.log`. Остановить автообновление: `sudo rm /etc/cron.d/servicedesk-update`.

## Уведомления в Max

Нужен бот Max. Создаёт его владелец организации на платформе «MAX для партнёров» (нужен подтверждённый профиль организации, ИП или самозанятого), бот проходит модерацию. После создания там же берётся токен бота.

1. Добавить в `/opt/servicedesk/.env` строку `MAX_BOT_TOKEN=токен` (без кавычек).
2. Перезапустить приложение: `cd /opt/servicedesk && sudo docker compose up -d --force-recreate app`.
3. В логе (`sudo docker compose logs --tail 20 app`) в строке `API: ...` должно быть «внешние уведомления: Max».
4. Каждый сотрудник открывает на сайте «Профиль», нажимает «Подключить Max», переходит по ссылке на бота и нажимает «Начать». Сайт сам запоминает его аккаунт Max и включает уведомления. Если ссылка не открывается, сотрудник присылает боту показанный на сайте код. Кнопка «Проверить» отправляет тестовое сообщение.

Сервер сам забирает сообщения у Max, поэтому открывать сервер из интернета не нужно. Нужен только выход сервера в интернет на `platform-api.max.ru`. Если Max потребует другой адрес (`platform-api2.max.ru` с сертификатом Минцифры), его указывают в `MAX_API_URL`.

## HTTPS (когда понадобится)

Домен для https не нужен: сойдёт собственный сертификат. Браузер при первом открытии покажет предупреждение, его подтверждают один раз.

1. Создать сертификат на 10 лет:

```bash
sudo mkdir -p /etc/servicedesk-ssl
sudo openssl req -x509 -nodes -days 3650 -newkey rsa:2048 \
  -keyout /etc/servicedesk-ssl/servicedesk.key -out /etc/servicedesk-ssl/servicedesk.crt \
  -subj "/CN=АДРЕС_СЕРВЕРА" -addext "subjectAltName=IP:АДРЕС_СЕРВЕРА"
```

2. В `deploy/angie.conf` раскомментировать блок `server { listen 443 ssl ... }` в конце файла.
3. В `.env` заменить адреса на `https://АДРЕС_СЕРВЕРА` (`PUBLIC_URL`, `ALLOWED_ORIGINS`) и поставить `COOKIE_SECURE=true`. Это же включает заголовки, которые велят браузеру открывать сайт только по https; пока сертификата нет, держите `COOKIE_SECURE=false`.
4. Открыть порт и перезапустить:

```bash
sudo ufw allow 443/tcp
cd /opt/servicedesk && sudo docker compose up -d --force-recreate
```

После покупки домена вместо собственного сертификата ставится бесплатный от Let's Encrypt. Это отдельный небольшой шаг.

## Резервные копии

Скрипт `deploy/backup.sh` делает копию базы и вложений в `/var/backups/servicedesk` и хранит 14 дней. Подключить раз в сутки в 3 часа ночи:

```bash
sudo chmod +x /opt/servicedesk/deploy/backup.sh
echo '0 3 * * * root /opt/servicedesk/deploy/backup.sh' | sudo tee /etc/cron.d/servicedesk-backup
```

Проверить вручную: `sudo /opt/servicedesk/deploy/backup.sh`, затем `ls -la /var/backups/servicedesk`. Желательно периодически копировать эту папку на другой компьютер или диск: копия на том же сервере не спасёт, если сломается сам сервер.

Восстановление базы из копии (приложение остановить на время загрузки):

```bash
cd /opt/servicedesk
sudo docker compose stop app
sudo docker compose exec -T db psql -U servicedesk -d postgres -c "DROP DATABASE servicedesk;" -c "CREATE DATABASE servicedesk OWNER servicedesk;"
gunzip -c /var/backups/servicedesk/servicedesk-ГГГГ-ММ-ДД.sql.gz | sudo docker compose exec -T db psql -U servicedesk -d servicedesk
sudo docker compose start app
```

Вложения: `sudo docker run --rm -v servicedesk_uploads:/data -v /var/backups/servicedesk:/backup alpine tar xzf /backup/uploads-ГГГГ-ММ-ДД.tar.gz -C /data`.

## Если что-то не работает

- **Сайт не открывается.** `sudo docker compose ps`: все три контейнера должны быть `running`, `db` ещё и `healthy`. Затем `sudo ufw status`: порт 80 открыт.
- **Приложение не стартует, в логах про базу.** Проверьте `DB_PASSWORD` в `.env`. Если пароль меняли после первого запуска, база помнит старый: либо верните старый, либо смените его в базе (`ALTER USER servicedesk PASSWORD '...'`). После правки `.env`: `sudo docker compose up -d --force-recreate`.
- **Вход не проходит, «Запрос с чужого адреса отклонён».** Приложение сравнивает адрес сайта в браузере с адресом, на который пришёл запрос. С Angie из этого репозитория (заголовок `Host $http_host`) это работает при любом адресе и порте. Если ошибка осталась, проверьте `deploy/angie.conf` (должно быть `proxy_set_header Host $http_host;`, а не `$host`), перезапустите Angie (`sudo docker compose up -d --force-recreate angie`) и впишите адрес из браузера в `ALLOWED_ORIGINS` точно, с `http` и портом, если он есть.
- **Запрещено после входа.** Адрес в браузере должен совпадать с одним из адресов в `ALLOWED_ORIGINS`, включая `http` или `https`.
- **Ошибка 502 от Angie после обновления.** Подождите 10–20 секунд, пока приложение запустится. Если не проходит, смотрите `sudo docker compose logs --tail 50 app`.
- **В Max ничего не приходит.** В логе приложения (`sudo docker compose logs app | grep max`) видны причины: «HTTP 401» значит неверный токен, «fetch failed» значит нет выхода в интернет. Бот отвечает только после модерации.
- **Уведомления приходят с задержкой.** Проверьте, что в `deploy/angie.conf` для `/api/events` стоит `proxy_buffering off`.
